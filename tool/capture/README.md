# Съёмка промо-материалов

Два скрипта, которые открывают собранную игру в Chromium 1920×1080 и
**играют в неё**, а не изображают игру: перетаскивают фигуры, доводят
уровни до конца, ходят по экранам. Из этого получаются ролик и скриншоты.

```bash
npm run build
npx serve dist -l 4180          # в отдельном окне
node tool/capture/record-video.mjs      # → raw/*.webm
node tool/capture/screenshots.mjs       # → shots/*.png, 1920×1080
```

Готовый ролик собирается из `.webm` так (лимит каталога — 30 секунд):

```bash
ffmpeg -ss 1.6 -t 20 -i raw/*.webm -f lavfi -i anullsrc \
  -vf "fps=30,scale=1920:1080:flags=lanczos,fade=t=in:st=0:d=0.5,fade=t=out:st=19.2:d=0.8" \
  -c:v libx264 -crf 20 -pix_fmt yuv420p -c:a aac -shortest \
  -movflags +faststart promo/gameplay-16x9.mp4
```

## Как они попадают по клеткам

Доска принимает координаты, а не клики по элементам, поэтому скрипты
спрашивают у самой игры, куда ставить фигуру: если активна подсказка —
берут клетку, обведённую золотым (`stroke="rgba(249,216,104,0.6)"`), в
обучении — точку, где заканчивается стрелка (`<circle r="4">`). Своего
знания решений у скриптов нет.

**Первый уровень принимает только перетаскивание**, тап появляется со
второго — поэтому ход делается настоящим drag'ом с промежуточными
`mouse.move`, иначе игра его не увидит. Это же ограничение делает
обучение непроходимым с пульта, см. этап 3 в
[ROADMAP.md](../../docs/ROADMAP.md).

С четвёртого уровня игра перестаёт показывать стрелку и предлагает
лампочку, поэтому дальше третьего уровня автоматика не проходит. Для
кадров со сложной доски нужно передать скрипту готовое решение.
